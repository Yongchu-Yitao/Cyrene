# Cyrene Doctor

Doctor 检查配置、插件、对话故障和项目记忆。基础检查不需要模型；Agent 分析是额外的一层，即使模型不能调用，检查结果仍然可用。

## 使用入口

- 设置 → Cyrene Doctor：检查应用配置及插件。
- 对话错误卡 → Cyrene Doctor：带入当前项目和对话，关联近期错误、记忆状态与后台 Hook。
- 记忆页工具栏 → Cyrene Doctor：检查当前项目的学习任务。
- Electron 后端启动失败：本地恢复页提供离线检查和重试启动。即使 Python 不可执行，也会保留安装/运行时排查方向。

命令行可以在服务未启动时检查，默认不写入数据、不加载自定义插件：

```sh
cyrene doctor --offline
cyrene doctor --offline --chat <chat-id> --project <project-id>
cyrene doctor --offline --json
```

可用 `--base-dir` 和 `--plugin-dir` 检查指定安装的数据目录；`--lang zh|en` 控制语言。退出码 1 表示发现失败项，0 表示没有失败项；报告中的 unknown 仍表示该检查未完成，并非全部健康。

## 结果含义

通过、发现问题、无法检查、正常跳过和信息提示分开显示。数据库检查是有时间限制的只读检查，不向真实记忆写入测试数据。项目记忆已更新而原对话仍使用冻结快照，会显示为信息提示；不会建议清空记忆。

记忆提交处理会记录阶段和跳过原因。旧版本留下的任务没有这些证据时，Doctor 会说明可能尚未触发，不能把推测当确定原因。Hook 队列会列出失败、阻塞和运行中的投递；仅运行时间长不代表任务僵死。

“让 Agent 分析”使用独立 ContextTree 和有限工具，只能查询当前报告的证据并提交分析；它不继承用户 SOUL、记忆、Skills、MCP 或普通文件/终端工具。最多进行 4 轮模型调用；断流、响应格式异常或超时可共享最多 2 次额外恢复请求（合计最多 6 次）。单次请求预算 45 秒，整体分析预算 180 秒，支持取消。恢复只补发失败的诊断请求，保留已有证据，不重放工作工具；输出截断时提高有限的输出预算。页面显示自动恢复进度。分析所用模型通过现有模型网关访问；对话诊断沿用对应的模型选择。模型不可用时保留基础报告及处理方向。

“测试模型连接”发送最小测试请求，可能产生少量模型用量，不发送真实对话内容。

## 修复与回滚

先查看方案，再执行具体动作：

- 恢复一个内置插件的发行版实现。原文件、额外文件与基线清单保留在备份中；目标发生变化时旧方案失效。恢复后重新加载并复检。
- 移除一项工具名称/描述/可见性/删除覆盖。配置使用 revision 校验，保留原覆盖值供回滚。
- 重试指定失败或冲突的项目记忆任务。必须仍有对应的原始证据快照和来源对话；不会用新的对话内容替代旧证据，也不会批量重放其他 Hook 或成功任务。

配置与插件恢复要求相关运行空闲。修复期间阻止新运行进入；有活跃记忆学习时暂不执行。操作完成后可以查看复检报告。插件/配置的回滚同样检查修复后是否又有改动，避免覆盖新修改。学习重试和模型请求没有通用回滚。

原始备份路径保留在修复结果中。进程被强制结束时不保证自动回滚；修复状态和备份用于后续恢复。数据库损坏、解密密钥丢失或缺失的历史学习快照只给出处理方向，不尝试猜测或重建用户数据。

## 数据与验证

报告保存在数据目录的 `doctor/reports`，运行故障的内容无关记录保存在 `doctor/incidents`。报告默认不包含对话正文、记忆正文、凭据或原始异常文本；可导出 JSON。故障记录保留分类、阶段、关联 ID 和不带源代码文本的调用栈位置。若报告存储本身失败，页面仍可显示当前基础结果。

自动化用例见 `tests/test_doctor.py`、项目记忆测试中的 Doctor 场景，以及 `electron/doctor-recovery.test.js`。测试使用隔离数据和可控模型响应，覆盖故障识别、降级、取消、修复、回滚、并发保护和精确重试，不需要真实模型额度。

## 统一错误接入

公共 HTTP 通道为 API 的 4xx/5xx 响应附加 `X-Cyrene-Incident-Id`，不读取请求和响应正文。未处理的 HTTP 异常及后台插件任务失败也会保存内容无关故障记录。前端捕获同源 API 失败、网络异常、未捕获 JavaScript 异常和 Promise 拒绝，显示持久的 Doctor 按钮；错误 Toast 没有其他操作时默认提供诊断操作。主动取消、外部请求与 Doctor 自身请求不触发重复提醒。

从错误打开会携带故障 ID 和客户端分类，只查询对应记录；记录过期或无法保存时明确显示证据缺失。客户端分类不是已确认根因。后端离线时弹窗提供本地恢复页和 CLI 排查说明。前端不采集 URL、异常正文、堆栈、请求或响应正文；同类错误短时间去重。

覆盖边界：被业务代码静默吞掉的错误、未进入公共请求通道的独立进程错误，以及前端代码初始化之前或整个操作系统崩溃造成的问题，仍需要专项接入或离线日志，不能承诺自动定位所有根因。
