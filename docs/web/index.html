Cyrene — AI Agent That Evolves

一个开源 AI Agent 框架：自进化人格、并行子代理、工作台风格桌面 UI，零基础设施。无需 Docker，无需 Redis，只要 Python。

Cyrene 是什么

Cyrene 是一个持续运行的 AI 代理。它拥有可自我重写的人格文件（SOUL.md），能在不同会话之间保持记忆，可以生成并行子代理协同工作，还能通过定时任务主动发起行动。

一切都在单一的 Python 进程中运行：

  • 一个进程托管代理循环、FastAPI Web 服务器、调度器和内置搜索引擎
  • 一个 Workbench UI：项目中心的桌面与浏览器体验
  • 任意 OpenAI 兼容 API（默认 DeepSeek；Claude、GPT、Qwen、本地模型都可以）
  • 零外部依赖：没有 Docker、没有 Redis、没有向量数据库服务

你也可以通过 Telegram Bot 或 WeChat Bot 与 Cyrene 交互。

核心特性

Agent Core

推理循环和让 Cyrene 不像无状态聊天机器人的核心机制。

  • 插件原生 Agent Runtime——同一个连续、可恢复的 Run 使用上下文插件、直接可见工具和 toolbox.list → describe → invoke 完成工作。详见架构。
  • SOUL.md 人格系统——Cyrene 维护一个可以自行重写的人格文档。它学习你的偏好、语气和项目，随着时间推移自行编辑 SOUL.md，人格不会在每次会话时重置。
  • 深度研究（Deep Research）——多轮研究管道：规划子问题 → 搜索和阅读 → 导出结构化 PDF 报告。
  • 深度反思（Deep Reflection）——面对复杂或模糊请求时，在内部多轮重构问题后再回答，以少量延迟换取更精准的回复。
  • 行为学习（Behavior Learning）——从过去的对话中提取可复用的行动模式，让重复工作流越来越高效。

记忆与知识

  • 三层记忆——上下文窗口 → 短期跨会话摘要 → 长期 SOUL.md。短期记忆带情感权重和提及次数追踪，高频条目自动保留。过时条目可"退休"而不被删除。详见记忆系统。
  • 知识库——上传文档、PDF 和图片；Cyrene 自动分块、嵌入和索引（包括图片视觉索引），代理可在任务中搜索和引用。无嵌入端点时自动降级到全文搜索。
  • 实体系统——跟踪结构化的项目实体（人员、系统、事项），提供创建、查询、更新、删除操作，可限定到 Workbench 项目范围。

工具与自动化

  • 文件操作——Read / Write / Edit / Glob / Grep，配合工作区范围守卫确保安全。
  • Shell 执行——执行 Bash 命令，支持持久 Shell 会话跨步骤复用。
  • Web 搜索与获取——配置官方 DeepSeek V4 模型时优先使用 DeepSeek Responses API 联网搜索，否则或调用失败时回退到内置 SimpleXNG（基于 SearXNG）；WebFetch 获取页面内容。
  • 知识库检索——代理通过 knowledge_tools 渐进披露并调用 knowledge.search，在工作区知识库中执行语义或关键词搜索。
  • 浏览器自动化——Electron 桌面版直接使用内嵌 Chromium（原生标签页、持久登录、无需 Playwright）；非桌面运行可选 Playwright 实时画面与登录接管。详见浏览器实况。
  • 并行子代理——生成独立代理并行执行任务，通过文件收件箱协调，支持 running → waiting → resumed → done 生命周期。详见子代理系统。
  • MCP 协议——连接 stdio 或 SSE 的 MCP 服务器扩展工具集，无需重启。详见MCP 协议。
  • 任务调度——Cron、间隔和一次性任务；抽奖系统让代理主动发起行动；管家代理维护 SOUL.md。详见任务调度。
  • 代码工具——代码库索引、符号搜索、调用链分析、Git 操作（diff / blame / log / status）。
  • 技能系统——在运行时安装 .md / .zip 提示技能，管理启用和卸载，无需重新部署。
  • 共享持久化终端——用户与 Agent 共用由独立 Daemon 托管的交互式终端。

界面与渠道

  • Workbench UI——项目中心化桌面体验：项目隔离、实时聊天与执行状态、Session、Browser、Knowledge、Memory、Schedule、Map 和 Settings。
  • Context Trace——每次 LLM 调用标记 _ctx 来源元数据，并可通过 JSONL、API 或 CLI 精确追溯上下文来源。
  • Electron 桌面应用——CI 自动构建 macOS、Windows（x64 + ARM64）和 Linux 包。凭据存在 OS 钥匙串，浏览器工具复用 Electron 内嵌 Chromium，不携带第二套 Playwright 浏览器。
  • 引导向导——首次启动自动运行，引导配置 API 密钥、模型和人格，无需手动编辑文件。
  • 地图引擎——AMap / Leaflet 交互式地图，支持标注点和路线。
  • Telegram / WeChat Bot——从聊天软件访问完整代理能力，支持双阶段循环和全部工具。

Cyrene — AI Agent That Evolves

An open-source AI agent framework with a self-evolving personality, parallel sub-agents, a workbench-style desktop UI, and zero infrastructure. No Docker, no Redis — just Python.

Cyrene is a continuously running AI agent with a self-rewriting personality file (SOUL.md), cross-session memory, parallel sub-agents, and proactive scheduled tasks.

Everything runs in a single Python process:

  • One process hosts the agent loop, FastAPI web server, scheduler, and bundled search engine
  • One Workbench UI: the project-centric desktop and browser experience
  • Any OpenAI-compatible API (DeepSeek by default; Claude, GPT, Qwen, local models all work)
  • Zero external dependencies: no Docker, no Redis, no vector database

Core Features

Agent Core

  • Plugin-native Agent runtime — one continuous, recoverable run uses context plugins, directly visible tools, and toolbox.list → describe → invoke discovery. See Architecture.
  • SOUL.md personality — a self-rewriting personality document maintained by a steward agent. Learns your preferences and evolves across sessions instead of resetting.
  • Deep Research — multi-round pipeline: sub-question planning, parallel search, source reading, and structured PDF report export.
  • Deep Reflection — reframes ambiguous or complex requests over several internal rounds before responding, trading latency for accuracy.
  • Behavior Learning — distills reusable action patterns from past conversations, making recurring workflows faster over time.

Memory & Knowledge

  • Three-layer memory — context window, short-term cross-session summaries (with valence tracking, mention counting), long-term SOUL.md. High-frequency entries auto-preserve; stale entries can be retired without deletion. See Memory.
  • Knowledge base — upload documents, PDFs, images; Cyrene chunks, embeds, and indexes them (including vision indexing for images). Falls back to full-text search without an embedding endpoint.
  • Entity system — track structured project entities (people, systems, items) with create/query/update/delete operations.

Tools & Automation

  • File operations — Read / Write / Edit / Glob / Grep, scoped by workspace guard.
  • Shell execution — run Bash commands with persistent shell sessions across rounds.
  • Web search & fetch — official DeepSeek Responses Web Search is preferred when a DeepSeek V4 model is configured, with built-in SimpleXNG (SearXNG) as the automatic fallback; WebFetch retrieves page content.
  • Knowledge search — the agent progressively discovers knowledge.search through knowledge_tools for semantic/keyword search over the workspace knowledge base.
  • Browser automation — Electron desktop uses its embedded Chromium directly (native tabs, persistent logins, no Playwright); non-desktop runs can opt into Playwright live view and login takeover. See Browser.
  • Parallel sub-agents — spawn independent agents with a stable actor-scoped wire bundle, coordinated via a file-based inbox. Main-only capabilities are rejected by runtime policy. Lifecycle: running → waiting → resumed → done. See Sub-agents.
  • MCP protocol — connect stdio or SSE MCP servers to extend the toolset without restarting. See MCP.
  • Task scheduler — cron, interval, and one-shot tasks. Proactive lottery system for agent-initiated actions. Steward agent for SOUL.md maintenance. See Scheduler.
  • Code tools — codebase indexing, symbol search, call-chain analysis, git operations (diff, blame, log, status).
  • Skill system — install .md / .zip prompt skills at runtime, enable/disable and uninstall — no redeploy needed.
  • Shared persistent terminals — user and Agent share interactive terminals owned by an independent daemon.

Interfaces & Channels

  • Workbench UI — project-centric experience with isolation, real-time chat and execution state, sessions, browser, knowledge, memory, schedule, maps, and settings.
  • Context tracing — every LLM call is tagged with _ctx provenance metadata and can be inspected through JSONL, API, or CLI.
  • Electron desktop app — CI-built packages for macOS, Windows (x64+ARM64), Linux. OS keyring credential storage and browser tools powered by embedded Chromium without a second Playwright browser.
  • Onboarding wizard — runs on first launch, guides API key, model, and personality setup — no manual file editing.
  • Map engine — AMap / Leaflet interactive map with pins and routes.
  • Telegram / WeChat Bot — full agent capability from messaging apps.

补丁 1：uvloop → winloop

import uvloop
uvloop.install()
# 为：
import sys
if sys.platform == 'win32':
    import winloop as uvloop
else:
    import uvloop
uvloop.install()

补丁 2：fork → spawn
编辑 Lib/site-packages/simplexng/_vendor/searx/plugins/calculator.py：

# 替换：
mp_fork = multiprocessing.get_context("fork")
# 为：
import sys
mp_fork = multiprocessing.get_context("fork" if sys.platform != "win32" else "spawn")

补丁 3：创建 pwd 存根
创建 Lib/site-packages/pwd.py：

"""pwd stub for Windows — SearXNG compatibility."""
import os
def getpwuid(uid):
    name = os.environ.get("USERNAME", "unknown")
    return type("pw", (), {"pw_name": name, "pw_uid": uid})()

补丁 4：启用 JSON API
编辑 Lib/site-packages/simplexng/settings/settings_template.yml，在 search.formats 中添加 json。

替代方案：如果不想打补丁，设置 SEARXNG_URL 指向外部 SearXNG 实例，并设置 SEARXNG_AUTO_START=0 禁用内置搜索启动。

配置

加密配置仓库、环境变量、运行时设置。无需 .env 文件。

配置架构

Cyrene 使用 Fernet 加密的 JSON 配置存储（data/config.enc）。这意味着：

  • API 密钥等敏感信息在磁盘上加密

  • 首次运行的引导向导会写入所有必需值
  • Web UI 设置页面可以在运行时更新配置

模型连接、档案与 primary / secondary / vision / embedding 路由以一份规范化配置图保存，并由 Provider Plugin 执行。

意图分流（Intent Dispatch）

聊天输入不是简单地全部交给 LLM。系统会自动分类意图：

  • 回答模式——直接交给 LLM 回答，不会触发工具调用或不必要的规划
  • 指令模式——需要调用工具执行的命令（如搜索、文件操作），交给代理执行
  • 任务模式——需要多步操作的复杂请求，生成执行计划逐步执行
  • 收尾——你说"任务完成"或"可以验收"时，代理汇总成果，状态标记为 review

你始终可以自由对话，不会无条件生成计划。

逐步执行

当代理进入任务模式时：

  1. Agent 规划需要执行的步骤
  2. 你决定步骤的执行顺序（不必按计划顺序）
  3. 每步执行时你可以在聊天中实时看到进度
  4. 你可以随时发送消息引导、调整或中止当前步
  5. 任务完成时，Agent 汇总成果，产物（文件、报告等）可在线查看或下载

Intent Dispatch

Chat input is automatically classified into intents:

  • Answer mode — direct LLM reply without tool calls or unnecessary planning
  • Command mode — tool execution such as search or file operations
  • Task mode — a complex request becomes a multi-step plan

You can always have a normal conversation; a plan is not generated unconditionally.

Step-by-Step Execution

When the agent enters task mode:

  1. The agent plans the required steps
  2. You choose the execution order; it does not have to match the plan order
  3. Progress appears live in chat while each step runs
  4. You can guide, adjust, or stop the active step at any time
  5. At completion, the agent summarizes the outcome and makes artifacts such as files or reports available to view or download

系统架构

插件原生 Agent Runtime

Cyrene 使用一套连续、可恢复的 Agent Run，不再把一次交互拆成路由和执行两套阶段。模型回复、工具调用、向用户提问、取消、恢复、上下文压缩和最终投递都属于同一个 Run。

用户消息
↓
上下文插件构建 Context Tree
↓
连续 Agent Run：回复、工具、Subagent、恢复
↓
持久化并投递最终结果

插件贡献

除 Bash、Read、Write 和 Toolbox 等必要 Kernel Tool 外，工具、工具包、独立工具、上下文、后台任务、页面与设置都由插件贡献。工具包和独立工具统一通过 toolbox.list → describe → invoke 发现，用户也可以把选定工具设为 Agent 直接可见。

文件读写 Bash Shell Web 搜索 知识库检索 实体管理 浏览器操作 代码分析 Git 操作 子代理生成 MCP 工具 任务调度 技能管理 共享终端

上下文与 Subagent

输入框上下文插件负责 Workspace、MCP、Skills 等会话选择；SOUL 插件启用时把人格挂载在 System Prompt 下方。Context Tree 的稳定 Block 可以复用缓存，长对话继续使用统一压缩机制。Subagent 继承 Main Agent 的初始 Tree，并附加 Main Agent 的任务指令，再通过 Inbox 协作。

Cyrene 自控制

cyrene_tools 是渐进披露的桌面自管理工具包。Agent 先用 cyrene.ui.snapshot 读取当前已渲染、当前视口中的稳定语义组件，再用 cyrene.ui.inspect 查看某个组件此刻可执行的动作，最后通过 click、type、scroll 或 drag 操作。导航、滚动、展开或打开右键菜单后必须重新读取 Snapshot；Inspect 不预测未渲染的下一页。

当前输入框的发送是显式 R2 动作，停止运行是 R1。项目、对话和数据后台 Service 保持 Internal，不直接暴露给 Agent。非模型设置通过 Typed Describe/Read/Write/Control 接口管理，写入使用版本比较并只更新指定字段，以免覆盖用户并发修改。

Architecture

Plugin-native Agent runtime, project structure, and security model.

Plugin-Native Agent Runtime

Cyrene uses one continuous, recoverable Agent run instead of separate routing and execution phases. Model output, tool calls, user questions, cancellation, recovery, context compaction, and final delivery all belong to the same run.

User message
↓
Context plugins build the context tree
↓
Continuous Agent run: replies, tools, subagents, recovery
↓
Persist and deliver the final result

Plugin contributions

Except for the required Bash, Read, Write, and Toolbox kernel tools, plugins contribute tools, toolboxes, standalone tools, context, background work, pages, and Settings. Toolboxes and standalone tools share toolbox.list → describe → invoke discovery, and selected tools can be made directly visible to the Agent.

File operations Bash shell Web search Knowledge search Entity management Browser actions Code analysis Git operations Sub-agent spawning MCP tools Task scheduling Skill management Shared terminals

Context and subagents

The required system-prompt plugin mounts the editable base Agent instructions first, while the kernel creates only an empty system root. The composer-context plugin owns per-chat workspace, MCP, Skills, and capability selections. When enabled, the SOUL plugin mounts personality immediately below the system prompt. Stable context-tree blocks preserve prompt-cache reuse, and long conversations keep the unified compaction behavior. A subagent inherits the main Agent's initial tree plus its assignment and then collaborates through the inbox.

Cyrene Self-Control

cyrene_tools is the progressively disclosed desktop self-management package. The agent reads stable semantic components in the current rendered viewport with cyrene.ui.snapshot, inspects a component's currently available actions with cyrene.ui.inspect, then uses click, type, scroll, or drag. Navigation, scrolling, expansion, and context menus require a fresh snapshot; inspect does not predict an unrendered next screen.

Submitting the current composer is an explicit R2 action; stopping a run is R1. Project, chat, and data business services remain internal. Non-model settings use typed describe/read/write/control operations with compare-and-set writes that update only named fields, preserving concurrent user edits.

记忆系统

三层记忆架构：上下文窗口 → 短期摘要 → 长期人格文档，自动压缩和持久化。

三层架构

Cyrene 的记忆分为三个层级，随着时间从短期向长期流动：

层级存储位置容量维护机制
上下文窗口data/state.jsonMAX_HISTORY_MESSAGES（默认 40 条）自动裁剪（FIFO）
短期记忆data/short_term.json压缩摘要（带情感权重和类型标签）后台压缩器定期运行
长期记忆workspace/SOUL.md结构化的自由格式文档管家代理按间隔审查和更新

记忆流动过程

  1. 每轮对话保存在上下文窗口中。超过 MAX_HISTORY_MESSAGES 条时，最早的条目被裁剪——但不会丢失，因为后台压缩器会处理。
  2. 后台压缩器定期将上下文窗口中的旧对话压缩为摘要，存入短期记忆。每条短期记忆包括：
    • 情感权重（Valence）——正面/中性/负面评分
    • 提及次数——同一主题被提到的频率
    • 条目类型——事实 / 模式 / 偏好 / 情感
  3. 自动保留规则——高频条目（≥3 次提及）和极端情感条目自动保留，不会被压缩器淘汰
  4. 管家代理按 STEWARD_INTERVAL（默认 30 分钟）运行，审查短期记忆和最近对话，通过 APPEND/ERASE/MERGE 命令更新 SOUL.md

记忆退休（Memory Retirement）

  • 该记忆停止被注入到上下文窗口中
  • 它不再被回忆或引用
  • 但文件本身不被破坏性删除

这比直接删除更安全——如果后续发现需要这个信息，仍然可以恢复。退休机制也避免了"已删除的记忆被重新学习"的问题。

Memory System

Three-layer memory: context window, short-term summaries, long-term SOUL.md.

Three-Layer Architecture

Cyrene divides memory into three layers that move from short-term to long-term over time:

LayerStorageCapacityMaintained by
Context Windowdata/state.jsonMAX_HISTORY_MESSAGES (40 by default)FIFO auto-trimming
Short-Term Memorydata/short_term.jsonCompressed summaries with valence and type labelsBackground compressor
Long-Term Memoryworkspace/SOUL.mdStructured, free-form documentSteward agent on an interval

Memory Flow

  1. Each conversation turn remains in the context window. When it exceeds MAX_HISTORY_MESSAGES, the oldest entries are trimmed after the background compressor has processed them.
  2. The background compressor stores summaries in short-term memory with valence (positive / neutral / negative), mention count, and a fact / pattern / preference / emotion type.
  3. Automatic preservation keeps frequently mentioned entries (at least three mentions) and entries with extreme valence.
  4. The steward agent runs at STEWARD_INTERVAL (30 minutes by default), reviews short-term memory and recent conversations, and updates SOUL.md with APPEND, ERASE, and MERGE.

Memory Retirement

Outdated or superseded short-term memories can be retired. A retired memory:

  • Stops being injected into the context window
  • Is no longer recalled or cited
  • Remains on disk instead of being destructively deleted

This makes recovery possible and prevents a deleted memory from simply being learned again.

概述

  • 拥有独立的思考过程和工具调用链
  • 超时后自动终止

子代理特别适合：同时搜索多个来源、并行分析多个文件、执行可分解的子任务。

Sub-agent System

Parallel execution, file-based inbox coordination, independent lifecycle.

Overview

Sub-agents are independent agent instances spawned dynamically by the main agent. Each one:

  • Receives a stable, actor-scoped wire bundle; discovery omits main-only actions and runtime policy rejects forbidden calls
  • Communicates with sibling agents through a file-based inbox
  • Has an independent reasoning process and tool-call chain
  • Stops automatically on timeout

They are especially useful for searching several sources, analyzing several files, or executing separable tasks in parallel.

Lifecycle

running
→
waiting
→
resumed
→
done / timeout
  1. running — sub-agent starts executing
  2. waiting — waiting for sibling results or inbox messages
  3. resumed — continues after receiving a message
  4. done / timeout — completed or timed out

The main agent collects all sub-agent results and synthesizes the final response.

Communication

Sub-agents coordinate through a file-based inbox system:

  • Each sub-agent owns an inbox directory
  • An agent writes a message to a sibling's inbox with send_agent_message
  • Inbox messages are read and handled in the next reasoning loop

Typical Use Cases

  • Parallel research — search several sources at once and combine the findings
  • Multi-file analysis — read and analyze several code files concurrently
  • Task decomposition — run research and data analysis as separate parallel tasks
  • Competing experiments — try multiple approaches and let the main agent select the strongest result

Considerations

Tip: Each sub-agent consumes tokens independently. Use parallel agents when concurrent work provides a real benefit.

抽奖系统（Proactive Lottery）

抽奖系统是 Cyrene 的一个独特功能——它让代理可以在没有用户输入时主动发起行动：

  • 每个心跳周期，代理有一定概率"中奖"

这个机制让 Cyrene 能够"主动"关心你，而不是只能被动响应你的提问。

Lottery System

The proactive lottery lets Cyrene initiate an action without waiting for user input:

  • On every heartbeat cycle, the agent has a chance to win
  • After a loss, LOTTERY_DELTA (0.15 by default) is added to the accumulated probability
  • The probability is capped at LOTTERY_MAX (0.85 by default)
  • A win resets the probability
  • It triggers only between DAYTIME_START and DAYTIME_END to avoid nighttime interruptions

This lets Cyrene check in proactively instead of responding only after a question.

  • Decide what should change in SOUL.md
  • Apply APPEND, ERASE, and MERGE commands
  • Remove expired TEMPORARY entries after 24 hours

Search

DeepSeek-native web search when configured, with a built-in SimpleXNG fallback.

DeepSeek First, SimpleXNG Fallback

When an official DeepSeek V4 endpoint (https://api.deepseek.com) and API key are configured, Cyrene first uses server-side Web Search through the DeepSeek Responses API, with deepseek-v4-flash as the documented search worker. Compatible third-party endpoints do not activate native search.

Without that configuration, or whenever the native request fails, Cyrene automatically falls back to SimpleXNG (based on SearXNG). It is zero-config, auto-starts on port 8888, and requires no Docker or external search key.

  • Automatic configuration — the manager generates data/simplexng_settings.yml
  • Automatic startup — a search instance starts on port 8888 with Cyrene
  • Proxy discovery — proxy configuration is handled automatically
Note: Native DeepSeek search consumes model usage on that account. Timeouts, authentication, rate limiting, protocol errors, and empty results fall back transparently to SimpleXNG. The old DuckDuckGo, Bing, and Baidu scrapers have been removed.

To use an external SearXNG instance:

# In Settings or .env
SEARXNG_URL=https://your-searxng-instance.com
SEARXNG_AUTO_START=0

Context tracing

Every LLM call is tagged with _ctx provenance metadata showing where each context block came from (system prompt, SOUL.md, short-term memory, history, tool results). Context tracing intentionally has no Workbench page; use the API, CLI, or canonical context-debug module:

curl http://localhost:4242/api/context-debug/events?limit=10

cyrene flow --session run_live --round round_xxx --id evt_3b22f9a5c0cb

uv run pytest -q

Note: Tests that call a real model use the Provider Plugin connections configured in Settings; other tests need no model credentials.

Project Conventions

  • Python 3.12+ with type hints on all function signatures
  • Ruff for linting (line length: 180)
  • Async/await throughout (asyncio)
  • Single responsibility per module. Cross-module communication via function calls, event bus, file-based inbox, and SQLite.

Adding New Tools

  1. Create the module in the matching domain under cyrene/tool_impl/ (for example knowledge/my_tool.py)
  2. Export TOOL_DEF (dict) and handler (async callable)
  3. Register the implementation in cyrene/tool_impl/__init__.py::NATIVE_TOOL_MODULES
  4. For a deferred tool, assign a stable capability ID in cyrene/tooling/packs.py::CAPABILITY_BINDINGS; changing the direct wire contract must be intentional
  5. Add policy/routing tests and optionally a UI settings entry

For MCP servers, use cyrene mcp add or the Web UI — no code changes needed.
