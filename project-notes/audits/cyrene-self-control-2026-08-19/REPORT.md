# Cyrene Agent 自我界面控制能力审计

日期：2026-08-19

## 结论

Cyrene 已经具备可用的“控制自己界面并调整自身”的能力，综合评价为 **8/10（模型服务现已纳入自控范围，安全边界总体强，但权限模式 UI 仍有一个需要优先补强的边界条件）**。

它不是仅靠屏幕坐标模拟点击，而是通过结构化语义树读取当前界面，再对声明过的节点执行点击、输入、选择、滚动和拖拽。对常用外观、语言、资料和通知设置，还能绕过可视界面，直接调用带类型校验和版本保护的设置接口。

模型服务页现在会进入 Agent 的语义界面树：连接、模型档案和路由按 R2 管理；API Key 以 R3 只写节点提供，Agent 可以提交新值，但界面树、快照与审计记录不会返回或保存明文。工具开关、Agent 行为、预算、更新、快捷键等全局设置同样需要本机用户对精确操作授权；读取秘密、主动提权、自行关闭自身、替用户回答授权仍永久禁止。

**对“Agent 能不能调整自己的权限”这个核心问题：正常路径下不能。** 权限模式不在可写设置 schema 中，`cyrene.permission.elevate` 被列为永久禁止；Agent 运行时模型/权限菜单入口也会 disabled。但如果用户在发送消息前已经把模型菜单停留在“权限模式”子页，发送动作不会主动关闭该菜单，子页中的模式按钮也没有单独 disabled 或 R3 标记，理论上可能被当前界面的通用 R1 点击能力利用。审计中未实际切换权限，但这是应优先封住的防御纵深缺口。

## 1. 读取当前界面 — 健康

- 支持 `snapshot` 和 `inspect`，返回结构化、分页的语义组件树，而不是截图坐标。
- 节点包含角色、名称、状态、允许动作和风险等级。
- 快照带 revision/lease；目标语义变化后旧动作会被拒绝，可防止“界面变了却点到别处”。

## 2. 操作当前界面 — 健康

- 支持单击、双击、文本输入、选择、滚动和拖拽。
- 设置页未显式标注的控件默认按 R2 处理；危险按钮可提升为 R3。
- 动作参数只能使用节点声明的 schema，选择器、XPath、脚本、URL、坐标和原始 IPC 字段被拒绝，避免把结构化接口退化为任意注入通道。

## 3. 直接修改自身设置 — 基本健康

- 设置注册表共有 55 个标量设置，其中 18 个允许 Agent 以 R1 直接修改：语言、时区、Telegram/微信通知、主题、强调色、字号/缩放、背景、动效、侧栏、昵称/简介、头像 emoji/颜色等；快捷键虽标记为 agent-writable，但整体操作提升为 R2。
- 其余设置主要是 R2：Agent 生成策略、主动消息、子 Agent 预算与运行上限、工具和工具包启停、预算策略、更新策略、开机启动、后台运行、快捷键等。
- 更新使用类型校验、范围校验、CAS revision 和幂等键，能防止并发覆盖及重复执行。

## 4. 模型服务与敏感字段 — 健康

- 模型服务连接、模型档案、用途路由和可见控制项会进入 Agent 的设置 schema 与自动界面投影。
- 普通 password/file/hidden input、`data-cyrene-secret` 和 `data-cyrene-user-ceremony` 控件仍不会进入 Agent 可见树。
- 模型 API Key 使用专用 `set_secret` 动作：输入参数名为 `secret_value`，风险为 R3，值不进入 `value_summary`，审计时自动替换为 `[REDACTED]`。
- OAuth 登录/登出显式按 R3 处理；删除按钮的 `danger`/`is-danger` 样式也会提升为 R3。

## 5. 授权边界 — 健康

- 自我管理能力仅主 Agent 可用，子 Agent 和其他调用方被拒绝。
- R2 自我配置需要本机桌面的人类确认，并绑定精确操作及参数哈希，只允许一次。
- Auto 和 Full Access 都不能绕过自我配置、破坏性操作、外部上传或生命周期确认。
- 主动/定时触发的 system-initiated 回合不能弹权限请求，因此不能趁用户不在时修改全局设置。
- 用户在当前本机请求中明确授权某个精确动作时，可由权限审查器签发一次性票据，避免重复询问。

## 6. 自身权限模式 — 需补强

- 设计层面：Agent 没有 typed capability 可改当前对话的 Default/Auto/Plan/Full Access；主动提权在操作清单中是 R4 forbidden。
- 常规交互：Agent 执行期间模型/权限菜单入口 `disabled={running || awaitingAnswer}`，因此不能在正常运行中打开菜单给自己提权。
- 边界条件：若用户发送前已经打开权限子菜单，`submit()` 没有关闭菜单，子菜单按钮也不随 `running` 禁用；通用 UI 投影会把主界面按钮默认为 R1。这形成“预先打开菜单时可能自改下轮权限”的静态可达路径。
- 建议：权限模式按钮全部显式标为 R3/`requires_capability`，执行期间无条件关闭并卸载菜单；服务端对权限模式变更再做一次仅真人来源校验，不能只依赖前端 disabled。

## 7. 主要缺口 — 需改进

1. **权限模式菜单的运行中残留（P1）**：优先修复上述“用户预先打开权限子页”条件，增加服务端来源校验和 E2E 回归测试。
2. **能力地图不够透明（P1）**：用户很难从产品 UI 看出哪些设置 Agent 能直接改、哪些会询问、哪些永远不可见。建议在每个设置旁展示“Agent：直接可改 / 需确认 / 不可访问”，并提供统一权限说明页。
3. **同一设置存在两条风险体验（P1）**：外观等 18 项通过 typed settings API 是 R1，但从设置页直接操作时，未显式标注的控件默认 R2，可能导致 Agent 走 UI 时多弹一次确认。建议为这些控件显式标 `data-cyrene-risk="R1"`，或让 UI 动作委托给 typed capability。
4. **界面覆盖依赖当前可见视口（P2）**：自动投影只收集当前 viewport 中的控件；长页面需要 Agent 正确滚动后重新取快照。能力可用，但比稳定 API 更容易受布局、虚拟列表和弹层影响。
5. **验证仍缺真实应用级闭环（P2）**：语义树和模型配置单元测试已覆盖，但建议再增加真实 Electron E2E：让 Agent 在空白配置中完成“添加服务商 → 填写只写密钥 → 添加模型 → 设置默认用途 → 确认实际对话使用新模型”。
6. **测试退出有后台任务告警（P3）**：Python 聚焦测试均通过，但 pytest 退出时仍报告 telemetry flush task pending，建议清理测试 teardown，避免掩盖真实异步泄漏。

## 证据与验证

- 真实 Electron UI 已检查：智能代理设置、工具管理、模型服务与权限模式菜单。
- 聚焦测试：Python 46 passed；Electron UI surface 10 passed。pytest 退出时有 2 条 telemetry task pending 告警。
- 未修改任何 Cyrene 设置或权限。
