# Cyrene 全面性能优化与等价性验证

2026-09-20。本轮在工作区实现了前次审计 10 类问题对应的保守优化。**固定版本的功能、消息内容、DOM、布局及动画对照未发现差异；不能将有限测试表述为全平台、所有输入和所有时序的绝对保证。当前共享工作区还有其他改动导致的测试失败，不能宣称整个仓库全绿。**

## 实现范围

| 原问题 | 本轮实现 | 保留的行为边界 |
|---|---|---|
| 保存合并、旧版投影反复扫描排序 | 接入已有有序合并快路径 | 重复/关联/无效日期/乱序等特殊情况继续走原算法 |
| 完成、等待等事件复制整条时间线 | 已知局部转换只比较可能变化的记录 | 新建、替换、多记录终止等结构事件继续完整比较；消息顺序、revision、输出隔离不变 |
| 未启用 DEBUG 仍序列化 | 先判断有效日志等级 | 启用日志时保留原脱敏、截断、错误记录逻辑及非抛出边界 |
| 静态历史消息反复渲染 | 简单标量消息快照 + React.memo | 流式消息、附件、trace、usage 对象、特殊卡片等继续普通渲染；回调、语言版本、日期、时区、图标变化可使缓存失效 |
| 终端历史逐字节 ASCII 解码 | 连续可打印 ASCII 成段处理 | UTF-8 跨块、无效字节、CR/LF、退格、控制序列、状态恢复保持原处理；pyte 屏幕模拟保留 |
| 调试日志扫描阻塞事件循环 | HTTP 扫描移至线程；文件摘要采用有界缓存 | inode、大小、mtime、ctime 变动失效；追加/覆盖/轮转/删除、近期事件覆盖和排序规则保留 |
| 缺失 token 查询全表扫描 | 添加缺失 token 的部分索引 | 旧库迁移、外部 NULL 写入和补算仍正常；不跳过一致性检查 |
| 事件数据库连接等待 GC 关闭 | 每次事务完成后确定性关闭连接 | commit/rollback 顺序、持久性设置、事件游标不变；未引入连接池 |
| 单个缓存 miss 阻塞其他 key | 按 key 协调加载、连接租借、元数据锁 | 同 key 合并加载、WAL 提交与依赖失效、结果隔离、淘汰与关闭安全；嵌套加载不持有第二把 key 锁 |
| 输入投影深复制已归档状态 | 复制输出所需字段时排除随后本就会删除的任务状态 | 不缓存模型输入，不减少传入模型的信息，不复用可变投影结果 |

消息组件主体与本轮开始快照逐字比较相同，仅增加外层渲染缓存。未修改 CSS、动画定义或持续时间。没有减少消息、采样丢弃终端字节、降低持久性或隐藏界面内容。

## 同机实验结果

以下为同一进程载入本轮改动前文件和当前实现，使用合成数据、重复采样的中位数；前端渲染使用同浏览器生产 React。它们是局部操作成本，不是远程模型生成速度。

| 场景 | 改动前 | 改动后 |
|---|---:|---:|
| 1,000 历史 + 1,000 新消息，保存合并 | 139.27 ms | 0.62 ms |
| 同上，旧版投影 | 138.82 ms | 0.52 ms |
| 5,000 条记录，单条完成事件 | 11.13 ms | 0.008 ms |
| 同上，无记录变化的等待事件 | 11.19 ms | 0.002 ms |
| 10,000 次关闭的 DEBUG 调用 | 71.42 ms | 2.58 ms |
| 约 2 MB ASCII 历史解析 | 464.63 ms | 10.66 ms |
| 50,000 条日志，重复摘要查询 | 143.61 ms | 4.86 ms |
| 100,000 节点，schema 检查及缺失 token 查询 | 8.37 ms | 0.044 ms |
| 无关 warm hit 遇到 50 ms 慢 miss | 约 50.20 ms | 约 0.06 ms |
| 40 节点各携带 1,000 条弃用归档，任务投影 | 23.61 ms | 0.051 ms |
| 2,000 条消息，增量提交及同步布局 | 38.2 ms | 7.9 ms |

渲染计数在独立插桩轮次验证：2,000 条简单静态消息，每次末条更新进入消息组件主体的次数从 2,000 次降至 1 次；耗时来自去掉计数插桩后的测试。每组 3 次挂载、各 5 次增量更新，另测试 100 个定时流式片段完整性。

**成本和未消除的工作：**

- 2,000 条消息首次挂载并未提速：本次中位数约 302.2 → 333.7 ms。快照与额外组件层有初始成本，收益主要发生在持续增量刷新；未做虚拟列表，以保留所有 DOM、选区和查找行为。
- 调试日志第一次摘要查询约 145.3 → 184.2 ms，因为还要构建并计量缓存；重复查询明显改善，HTTP 扫描不再占住事件循环。
- 事件库 200 次提交中位数约 343.1 → 349.9 ms，本次没有写入提速证据；确定性关闭使 GC 前残留的数据库文件描述符从 17 降为 0。
- pyte 全屏模拟仍有真实 CPU 成本。3 次实际终端流水线测试，每次 2,097,152 字节持久化及回放均完整，flush 为 209–219 ms，屏幕处理为 1,153–1,168 ms。没有跳过字符或更换终端模拟器来换取指标。
- 任务投影收益依赖废弃状态大小；上表是压力样本，不代表普通短会话也有同等倍数提升。
- 未引入跨运行的模型输入缓存，也未将所有结构事件改成未经证明的局部更新。以上保留项意味着不能说“所有设备相关开销已经消失”。

## 验证证据

- 精确改动前模块与当前模块差分：6,000 个随机时间线事件；600 组混合终端数据，6,923 次分块/恢复检查；300 组任务投影。比较输出、内部状态、后续事件是否污染之前输出及输入隔离，均通过。
- 新增保存合并及旧版投影差分：各 2,000 组，同一 JS realm、冻结输入；普通和回退路径均覆盖。
- 新增 9 项 Python 边界回归：同 key 合并、跨 key 并发、嵌套加载、在用淘汰、关闭、inode 替换、写入期间失效、异常重试、日志等级、文件变更/结果隔离、token 补算、数据库关闭和 HTTP 线程执行。
- 前端 Node 套件：**182/182 通过**；最终生产构建通过。
- 全量 Python 最后完整一轮：**3,199 通过、5 跳过、2 失败**。失败是其他文件新增私有跨包导入，见下一节。
- 真实 AgentSession 合成模型矩阵：19 个 session、92 轮、14,100 个片段，覆盖并发、40 轮历史增长、工具调用、5,000 片段输出以及关闭后重新打开；检查通过。模型和工具响应是合成的，不是远程供应商测速。

### 浏览器严格对照

同一份冻结前端，其余模块完全相同，仅替换本轮改动前/后的 messages、runtime-timeline、i18n 模块。真实 WbcMain、消息、输入框及产品 CSS，服务边界使用合成数据。

**33 个检查点均一致**：完整 HTML、文本、记录的元素几何与计算样式、操作回调、输入框内容、焦点、选区、滚动、节点保留、消息数。覆盖复制、编辑/取消、流式增量、历史滚动、选中文字、工具展开、深浅色、中英文、切换会话、移除、完成/取消/失败、语音可用状态、同语言翻译扩展和消息标量原地修改。

**47 份动画记录一致**：流式淡入、重试清除等，比较 timing、keyframes，以及 0/25/50/75/100% 时间点的 opacity/transform。动画在测试夹具中暂停取样；这不是所有设备帧率均相同的保证。

补充真实 HTTP 测试使用生产重连运行时及解析器：服务端提前断开、cursor=2 重连、重复事件回放、97 字节分块 JSON/UTF-8、新增/移除消息，然后分别完成、失败、取消。每条路径双方 16 条运行时记录一致、最终 119 条消息一致，恢复文字只出现一次。实际 WbcChatSplit 挂载后 238 行，两个滚动区域及 DOM/布局一致。

语音测试验证状态订阅和按钮显示，没有进行真实扬声器/音频设备验收。未完成 Windows/macOS 原生窗口、跨窗口拖动、真实远程模型服务或所有响应式断点的穷举验收。

### 验证中发现和处理的差异

初稿给消息主体增加了 i18n 订阅。这会引入原版没有的独立刷新机会，因此最终移除，改为父组件原有刷新时读取语言版本。最终消息主体与原版相同。

网络夹具初始一度出现双方时间文本和高度不同。移除订阅后差异仍可出现，不能把该次观测单独归因于订阅。夹具未固定本地初始语言，语言初始化与异步设置请求存在竞争；固定双方初始语言为 en 后，初始、网络终止及分屏对照通过。早期差异记录保留，没有删除失败证据。最终 33 组夹具还单独验证了中英文和同语言翻译更新。

## 共享工作区的其他失败与版本界限

全量 Python 的两项失败指向以下新增导入，本轮优化没有修改这些位置：

- `cyrene_sessions/__init__.py` → `_chat_application_port`
- `control/control_ports.py` → `inbox._inbox_payload`

随后针对当前工作区复跑相关 Python 检查，**412 通过、2 失败**。此时另一个改动向 `features/chat/context-panel.jsx` 加入 `window.cyrene.platform === "linux"`，触发两个目录选择器测试对整个聊天源码的字符串排除断言。上下文面板及两个语言目录相对浏览器固定快照已有变化，记录在 `source-drift.json`。未修改这些其他功能来掩盖失败，也没有把固定快照的结果当成对后续所有工作区变化的验证。

因此，交付结论是：本轮优化已有详细等价性和性能证据；已列明场景未发现功能/界面/动画差异；当前共享仓库的总体测试状态仍包含上述失败。
