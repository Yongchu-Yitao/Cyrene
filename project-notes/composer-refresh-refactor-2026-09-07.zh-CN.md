# 输入框状态与实时刷新重构

基于 main `4326790a`。本轮范围是性能归因、输入框状态归属和实时刷新重复查询；未推进聊天页面、模型协议解码器或 AgentSession 的下一轮拆分。

## 改动

- 草稿 Hook 负责加载、引用同步、300 ms 延迟保存、立即保存、会话切换时保存旧草稿，以及 pagehide/隐藏/卸载时清理。保留原会话切换边界、主窗口与其他 surface 的草稿命名空间。
- 上下文目录 Hook 负责请求、取消、失效和工作区目录记录；命令目录 Hook 负责按需加载与失效。命令请求在项目切换或失去请求归属时取消，旧结果不会写入新目录；修复旧 loading 标志可能阻止切换项目后发起新请求的问题。
- `/api/workbench/sessions` 增加可选 `include_status=true`。同一份会话投影供 sessions 和 status 使用；默认请求仍只返回 sessions，独立 `/api/status` 不变。
- 实时事件刷新仍使用 80 ms 合并窗口，但从两次请求改为一次。独立会话和状态刷新仍有各自的序列检查；共享请求不能因其中一项单独刷新而错误取消另一项。页面卸载取消全部在途请求。
- 状态投影失败时记录异常，HTTP 仍返回 500，保留原有错误诊断能力；响应携带独立成功的会话结果供前端更新，前端保留上一份状态。这保留原先两个独立刷新之间的失败隔离。
- 真实页面测试发现既有错误卡片诊断按钮使用未定义的 `t`；改用该模块已有的 `wbcT` 翻译入口，并增加实际 React 元素渲染和按钮回调测试。

## 复杂度

输入框本体 Hook 调用从 **72 → 56**，函数行数 **1594 → 1473**；决策计数仍为 **503**，本轮并未声称解决其全部渲染分支复杂度。

新提取函数均在默认预算内。匿名回调序号变化导致预算路径漂移：4 个回调按源码完全一致核对迁移，会话切换回调只将原有草稿步骤委托给草稿 Hook，其他语句不变。其 setter 目标数 **15 → 14**。输入框预算同时收紧，无指标上限提高。迁移记录见 `composer-budget-relocations-2026-09-07.json`。

## 性能证据

### 对此前聊天基准退步的复查

按 before/current/current/before/before/current 顺序，分别运行 3 repeats，共 6 次进程调用。baseline 为 `30835bb6`，current 为本轮修改前的 `4326790a`，使用同一 Python 环境和各自隔离数据目录。

| 场景 | 基线 p95 中位数 | current p95 中位数 | 差异 |
|---|---:|---:|---:|
| 双会话重工具 | 137.35 ms | 141.15 ms | +2.77% |
| 密集聊天 | 554.90 ms | 541.81 ms | -2.36% |
| 工具风暴 | 942.53 ms | 965.41 ms | +2.43% |

质量断言全部保持。单轮波动明显，不能从这些样本识别稳定的因果关系，也不能据此宣布此前退步全部解决。cProfile 对比实际执行过的源码：涉及上轮改动的 AgentSession/transition/plugin helper 模块主要发生导入，未执行其中业务方法。该基准不覆盖完整 AgentSession 模型执行或前端渲染。

同步修正性能文档中并不存在的 `agent` 组；当前入口实际支持 chat、search、features。数据见 `composer-refresh-performance-2026-09-07.json`。

### 本轮实时刷新优化

真实本地 HTTP、同一后端与隔离会话数据。旧方式并发请求 sessions/status，新方式一次请求 include_status；ABBA 交替，排除 4 次预热，每种方式 30 个样本，所有返回数据逐项一致。

| 指标 | 两路并发请求 | 合并请求 |
|---|---:|---:|
| 每次刷新请求数 | 2 | 1 |
| 每次刷新会话投影次数 | 2 | 1 |
| 中位耗时 | 12.42 ms | 7.30 ms |
| p95 | 13.97 ms | 8.43 ms |

只证明本机该固定场景的刷新开销降低，不外推为所有聊天性能提升。数据见 `realtime-refresh-performance-2026-09-07.json`。

- 初次新增异步测试对跨 VM 微任务等待不足，改为等待一轮事件循环后通过；后续只重跑受修改影响的测试。
- Ruff、Python 复杂度（9727 scopes）、JavaScript 复杂度（11174 scopes）、WebUI 构建、diff 格式检查通过。最终错误隔离调整后额外定向复验 Python 13 项和相关前端测试均通过。

没有提交或推送本轮改动。工作期间出现其他任务对聊天 shell.css 的修改，保留原样，不计入本轮重构成果。

浏览器脚本在请求监听回调使用 URL 构造器时两次断连；改为字符串解析路径后，剩余输入与请求检查通过，未进一步定位自动化工具内部原因。测试使用复制的临时配置和受控失败响应，没有请求真实模型。
