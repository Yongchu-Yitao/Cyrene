# 性能优化严格等价复核

日期：2026-09-20。约束：绝对不能影响任何功能；本轮只核对，没有将优化写入产品代码。

## 当前决定

**两个现有原型均不能直接合入。** 上轮证明了局部计算可以更快，没有证明完整功能等价。撤回任何可被理解为“已经确认安全、可直接落地”的表述；前端仍是优先研究项，但需先补齐输入边界和产品级验证。

有限测试不能证明对任意输入、并发交错、平台和故障都绝无影响。这里将用户要求作为接受变更的硬约束：存在已知行为差异，或关键功能验证未完成，就维持当前产品实现，不以加速收益抵消功能风险。

## 前端合并原型

对旧实验脚本中的原型与当前 `runtime-timeline.jsx` 做差分验证，两者在同类 Node VM 中运行，未改动产品源文件。

- 12,000 组消息合并：已生成的密集数组样例未发现差异。
- 6,000 组现代／旧式投影：已生成样例未发现差异。
- 154,188 次对象引用检查通过；输入递归冻结，验证不能原地修改输入。
- 样例包括重复及空 id、同时间、有序／无序、无效／缺失时间、旧时间字段、乐观消息、请求关联、问答关联、工具卡片、checkpoint revision、运行状态、待回答与重连状态。

**反例：稀疏数组。** `base = Array(1)`，再添加一条有有效时间的消息：旧算法返回带原空槽的合并数组；原型读取不存在元素的 `at` 字段，抛出 `TypeError`。结果 JSON 将数组空槽显示成 `null`，实际测试输入是空槽，不是显式 null。

JSON 网络输入一般为密集数组，当前未证明生产路径会产生这个反例；同样没有输入合同保证所有调用路径永远密集。它因此是原型缺少前置条件的证据，不是“用户已经遇到崩溃”的证据。

该合并函数不只供主聊天列表使用：还用于乐观用户消息、保存后水合、旧式活动投影、分屏问答及远程事件更新。全局替换的影响范围比单个长历史基准更大。

进一步实现必须将快路径限制为可证明的输入域：密集普通数据数组、可解析且有序的时间、无特殊关联处理；任何不满足条件的情况完整回退旧算法。对该域可按稳定合并归纳论证顺序及去重等价：处理每个新增项前，known 与旧实现相同；重复项均忽略；非重复项置于第一个严格晚于其时间的项目之前；相同时间保持已有项及新增项的先后顺序。但还需明确非普通对象、getter、特殊原型及异常行为的输入合同，不能把这段论证外推到任意 JS 对象。

性能原型还增加了装饰数组等临时分配，未验证真实页面的峰值内存和 GC，也未验证所有浏览器交互。此次不会仅修掉空槽反例后就宣称整体安全。

## 后端局部完成原型

上轮 `targeted_done` 本来仅用于测量“明确存在的一条回复首次完成”的成本，本轮对照进一步确认它不能用作 `RunTimeline.apply` 的替代。

| 复核输入 | 原型与当前实现的差异 |
|---|---|
| 完全相同的完成事件重复两次 | 原实现第二次不发布变更记录，保留该记录的 timelineRevision；原型再次标为变化并更新记录 revision |
| 相同 eventId 重放 | 原型未维护 seen，也未执行去重 |
| 同时有 response 与 text | 原实现优先 response；原型只读取 text |
| text 为 null | 原实现保留已有正文；原型写入 None |
| text 为数字 | 原实现转字符串；原型保留数字 |
| messageId 尚不存在 | 原实现创建记录并维护活动成员关系；原型 KeyError |
| payload 内覆盖正文 | 原实现合并嵌套 payload；原型忽略嵌套值 |

这些都是已复现的差异。8 组明确样例中，仅原定单次普通完成样例完全等价，其他 7 组不等价。它们不能被以“速度提升很大”为由接受。

未来可以研究只替换原实现的 before-image 和变更检测成本，保留整个事件入口、分派与状态处理。必须逐事件比较 patch、revision、seen、sources/tools/reasonings 映射、记录顺序、snapshot、历史快照隔离，以及最终落盘／重放结果。不能仅比较最终可见文字。

特别需保留：用户插话只关闭成员关系、不丢失流归属；迟到工具结果回到原卡片；取消只影响所属输出；无变化事件与重复 eventId 的不同 revision 行为；终结时所有未完成记录和工具正确收尾。

## 其他候选的重新定级

均为待研究，当前不接受直接实施：

- **数据库连接复用**会改变线程所有权、排队、关闭、回滚及数据库文件替换时的行为。保持 SQL 相同并不自动证明等价；尤其不能扩大落盘窗口或更改同步级别。
- **缓存锁拆分**会增加原本被串行化的交错。必须保证淘汰不关闭租借中的连接、同 key 合并加载、WAL 提交检测、插件归属失效、返回对象隔离及内存上限。
- **日志索引／移出事件循环**需保留轮转、截断、损坏行、同 id 覆盖、排序和完整详情。线程化也会改变取消与并发时机。
- **迁移检查缓存**不能遗漏旧库、外部写入、恢复与缺失 token 计数，不能只通过进程内“已初始化”标记绕过检查。

## 补验结果

当前权限环境已与上轮不同；配置仍隔离到临时目录。工作区还有其他并行修改，当前源码测试结果不能充当上轮源码与某个优化版本的正式 A/B 结果。

| 检查 | 本轮结果 | 能证明什么 |
|---|---|---|
| Python 时间线、缓存、HTTP 客户端、聊天恢复、事件作用域 | 60/60 通过，无排除 | 当前实现满足这些现有用例 |
| 前端 chat 目录现有测试 | 110/110 通过 | 当前实现满足这些现有用例 |
| 上轮超时的 live checkpoint 用例 | 本轮包含在 60 项内并通过 | 不应继续标记为稳定复现的产品缺陷；原因未作因果确认 |
| features 基准 | 未完成 | 45 秒诊断超时，输出线程栈期间进程最终 exit 139 / segmentation fault；根因未定位，不能宣称基准通过或认定某个优化导致崩溃 |

现有产品测试通过，不等于这些测试已对优化版通过。差分实验比较的是两个实验原型；没有对完整优化后的产品进行端到端验证。Windows/macOS/Android、真实 UI、崩溃恢复和长时间并发验证仍缺失。

## 后续接受标准

保持现有模型、参数、上下文内容及顺序、工具集合与执行约束、权限流程、事件完整性、落盘和恢复语义。界面中的历史、附件、分屏、重连、查找、选择复制、导航和无障碍也不能减少或退化。

只允许小范围、可回退的等价计算替换。每个变更都须有明确输入域、旧实现差分证据、所涉及功能的集成验证和真实负载性能结果。存在未解释差异或未完成关键验收时，维持原实现。这是“不牺牲功能”的准入规则，不是测试能给出的数学意义上的无限范围保证。

本轮证据位于 `project-notes/experiments/performance-2026-09-20/`：

- `equivalence_recheck.mjs`、`equivalence-recheck.json`：前端差分及稀疏数组反例。
- `backend_recheck.py`、`backend-recheck.json`：后端反例与逐步状态／patch 对比。
- `recheck-python-tests.log`、`recheck-frontend-tests.log`、`recheck-features.log`：测试与未完成基准的真实输出。
