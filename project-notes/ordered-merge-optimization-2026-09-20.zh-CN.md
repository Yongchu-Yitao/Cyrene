# 消息投影合并优化与验证

## 范围

只优化 `wbcProjectTranscript` 的最终消息合并入口。符合条件的有序普通消息数据使用稳定线性合并，预解析时间并保留原对象引用；不满足条件时调用原算法。公共合并函数及消息渲染组件保持原样。

门槛为新增消息至少 8 条，且 M × (N + M) 至少 4096。稀疏数组、访问器、自定义数组方法、无效或逆序时间、用户消息和特殊关联字段等进入原路径。相同时间的先后关系、重复 ID、空 ID 和已有对象引用保持原语义。

本次提交从独立源码快照构建，未纳入工作区其他任务的未提交改动；运行时消息移除支持等其他改动也未混入。

## 验证

- 本次提交的独立快照：完整前端 Node 测试 **178/178** 通过；正式构建通过。
- 新增 `ordered-merge.test.mjs`：覆盖快路径实际命中、同时间稳定性、重复/空 ID、引用保持、异常数据回退、getter/自定义方法调用一致性、10,000 组确定性差分，以及时间线事件重放和终止状态。
- 前期工作区验证：57 项时间线、滚动、分屏、导航、重连、重试和选区相关 Python 契约通过；额外 2,000 组长会话投影对照通过，1,105 次命中快路径。
- 浏览器固定快照 A/B：实际聊天主区域、会话导航、输入框、分屏组件和 21 个受控检查点一致。验证历史阅读位置在增量更新时保持、返回最新消息、编辑开关/多行输入及保存参数、分屏消息更新和交接。
- 实际 HTTP 流提前关闭后，使用产品解析器及运行时自动携带 cursor=2 重连；重复事件、后续增量、移除和终止事件的两侧状态轨迹一致。完成、失败、取消三种路径最终均为 119 条唯一消息，正文没有重复追加，DOM、所测样式/尺寸和滚动状态一致。

前期浏览器验证使用合成数据及部分服务替身；其快照还包含当时已有的其他工作区改动。本次独立提交通过自身的完整前端测试及构建，不把前期整份工作区的结果误表述为本次提交的完整端到端验证。
