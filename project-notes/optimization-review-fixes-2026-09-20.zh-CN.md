# 性能优化 Review 的四项修复与验证

2026-09-20。本轮修复 [详尽 Review](optimization-detailed-review-2026-09-20.zh-CN.md) 中的四项问题，产品改动限于日志摘要仓库、终端历史解析器、消息 memo 辅助模块；另外更新了对应回归测试和构建产物。未改动消息组件 DOM、CSS、动画定义、输入行为或终端屏幕模拟器。

## 修复状态

| 问题 | 修复 | 验证 |
|---|---|---|
| 临时读取失败缓存成空/部分日志 | 只有完整读至 EOF、正常关闭且文件元数据稳定，才安装缓存 | 首次 open 失败与读取中途失败后，下一请求均恢复完整结果；失败时不留有效缓存 |
| Unicode 缓存计量触发 500 | 用 ASCII 转义后的长度计量；计量失败只放弃缓存 | 原复现 HTTP 请求：原版及修复版均返回 200、相同的最新事件；连续第二次命中缓存也通过 |
| 生产元数据使消息 memo 失效 | 为 `usage`、`latestRequestUsage`、`modelIdentity` 建立独立的平坦字段快照并比较 | 真实字段形状下，每次增量只渲染 1 个消息主体；元数据原地修改、替换、删除均正常刷新 |
| 中文和密集 ANSI 解析退步 | 用正则在 C 层寻找 ≥16 字节的 ASCII 段；其余内容回到原逐字节循环；复用 256 个不可变单字节对象 | 中文、混合文本更快，密集 ANSI 与原版持平；逐字节输出及状态保持一致 |

缓存快照继续拒绝 getter、数组、未知复杂嵌套对象和特殊卡片，保留普通渲染回退。不会通过删除 usage、模型身份、附件或 trace 获得性能收益。完整读取中的坏 JSON 行仍按原策略跳过，临时 I/O 错误的当次部分返回语义也保留。

## 性能复测

本轮比较基准是**全面优化前的精确文件快照**，不是有缺陷的 review 版本。性能测量与全量测试分开运行。终端实验同进程、交替执行顺序、512 KiB 输入、4 KiB 分块，预热后各 5 次取中位数。

| 终端历史解析样本 | 原版 | 修复版 | 结果 |
|---|---:|---:|---|
| ASCII 行 | 126.17 ms | 20.29 ms | 约快 84% |
| 中文行 | 134.19 ms | 107.00 ms | 约快 20% |
| 密集 ANSI 颜色控制 | 53.79 ms | 53.62 ms | 基本持平 |
| 中英文与 emoji 混合行 | 136.58 ms | 113.26 ms | 约快 17% |

四类输入均比较所有行及最终解析器状态，输出一致。短 ASCII 段不再承担逐字节正则探测成本；性能表并不意味着任意分块尺寸、任意设备都有固定比例收益。

浏览器使用生产 React、实际消息组件，以及由 `runtime_model_message_fields()` 生成的历史消息元数据。每组 3 次挂载、各 5 次增量更新；渲染计数与无插桩耗时分别测量。

| 消息场景 | 原版每次主体渲染数 | 修复版 | 原版增量提交/同步布局 | 修复版 |
|---|---:|---:|---:|---:|
| 1,000 条历史 + 1 条更新 | 1,001 | 1 | 9.1 ms | 6.6 ms |
| 2,000 条历史 + 1 条更新 | 2,001 | 1 | 17.6 ms | 11.3 ms |
| 1,000 条历史 + 1,000 条实时记录 | 2,000 | 1 | 39.4 ms | 10.0 ms |

计数旧值已由 review 轮次验证；本轮重新验证修复后的计数，并独立重测双方无插桩耗时。上述历史记录包含正常 usage/model 元数据，已不再依赖省略元数据的简化样本。

首次挂载仍有快照/包装层成本：2,000 条历史 + 1 条更新场景约 296.8 → 312.2 ms；1,000 条历史 + 1 条更新约 160.9 → 182.5 ms。没有把首次挂载宣称为提速，也没有使用虚拟列表隐藏历史节点。

## 功能与界面验证

- 新增 5 个 Python 回归实例：打开失败恢复、读取中途失败恢复、孤立代理字符位于 limit 外的 HTTP 查询、缓存计量异常、长 ASCII 段跨控制/UTF-8/状态恢复边界。
- 新增 2 个 Node 测试，覆盖生产元数据命中、修改/删除/null 转换、getter/数组/复杂对象回退及 `__proto__` 数据字段；消息 memo 文件共 5 项通过。
- 第一轮相关 Python 测试 **35/35 通过**；完整前端测试 **184/184 通过**；生产构建成功。
- 重跑精确差分：**6,000 个时间线事件、6,923 次终端分块与恢复检查、300 组任务投影一致**。
- 真实终端流水线独立运行 3 次，每次 **2,097,152 字节输入 = 持久化字节 = 回放字节**；屏幕解析照常执行。flush 约 204–213 ms，未丢字节。
- 实际聊天界面 **36 个检查点全部一致**：完整 HTML、文本、所采集的布局与计算样式、输入、焦点、选区、滚动、节点保留及回调。包括编辑、复制、深浅色、中英文、流式输出、切换会话、完成/取消/失败、语音状态等；额外加入 usage 原地改变为 999、替换为 888、删除后数值消失的断言。
- **47 份动画记录一致**：timing、keyframes，以及 0/25/50/75/100% 的 opacity/transform 采样。未调整动画持续时间或关闭产品动画。

浏览器两边共享冻结的其余前端模块，只替换优化前/当前的相关实现；最终 SHA 和快照记录在实验目录。服务数据是合成数据，语音验证覆盖状态和按钮，不是物理音频设备验收。本轮没有重新穷举其他桌面平台、远程模型或全部原生窗口操作；有限验证不能作为任意环境下绝对零差异的证明。

## 全量工作区测试状态

全量 Python：**3,216 通过、5 跳过、5 失败**。失败均位于本轮未修改的其他工作区内容：

1. 私有跨包导入数量检查。
2. 私有领域/兄弟插件导入边界检查。
3. 新增 `cyrene_sandbox` 插件缺少显式 i18n pack 条目。
4. 原生目录选择器的源码断言。
5. 聊天目录选择器的源码断言。

后两项由上下文面板里的 `window.cyrene.platform === "linux"` 触发整段聊天源码的排除断言。本轮没有修改架构基线、插件目录或这些断言来让测试变绿。四项 review 修复及其新增回归已通过，但不能把当前整个共享仓库称为全绿。
