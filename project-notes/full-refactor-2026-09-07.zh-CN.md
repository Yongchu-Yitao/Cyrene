# Cyrene 复杂度重构：本轮改动与验收

日期：2026-09-07。工作区基于 main，当前改动尚未提交或推送。本报告描述本轮增量，前一轮的草稿、资源加载、实时刷新、页面状态改动另见同目录已有报告。

## 取舍与范围

功能、特性和用户体验保持不变是约束。根据本轮用户明确的性能取舍，可维护性改善优先于微基准中少量毫秒的差异；性能关注实际卡顿、首字延迟、吞吐和资源生命周期。本轮没有为追平极小差异增加补偿逻辑。

实现覆盖六个研究方向的具体职责：聊天状态写入、输入设置、发送请求元数据、Electron 标签选择器生命周期、流式协议解码、会话事件发布；同时简化 Rail/Topbar 的数据投影并增强复杂度检查。这不意味着整个项目已消除所有大函数，或已经完成所有潜在架构改造。

## 具体改动

1. **分屏选择集中管理**：增加 split-selection-state.jsx，四类分屏选择由单一状态所有者执行 select、close、restore、prune。保留历史快照中的多槽数据、对象身份、无变化时的引用以及过期关闭保护。控制器不再分别调用四套原始 setter。
2. **输入设置集中管理**：增加 composer-settings.jsx，统一模式、Soul、工作区、短期记忆、项目记忆和上下文激活设置。保留首次挂载与切换对话时的不同默认规则、显式 false、资源可用性规则及草稿/附件处理顺序。
3. **发送请求数据分组**：SendOrigin 与 SendOptions 是只读字段记录，替代发送操作中的 15 个散落字段。保留原有输入类型转换，以及附件 await 前后两个解析时点；不改变可变消息、回滚、预算和工作流行为。
4. **Electron 标签选择器独立管理**：BrowserTabPicker 接管原生视图、挂载窗口、准备状态、隐藏计时器、模糊事件和销毁。通过窄接口获取标签与宿主信息。选择、刷新、静音、关闭标签动作仍由 BrowserTabManager 执行；220 毫秒隐藏时序与安全偏好保持原样。
5. **流式协议解码集中管理**：StreamDecoder 管理 Anthropic、Responses、Gemini、OpenAI 兼容协议的文本、推理、工具调用与用量累积。HTTP/SSE、计时、trace、错误检查仍在原适配器。消除工具参数每个片段重复创建后又丢弃的默认记录/UUID，以及空工具集合的无效排序。
6. **会话事件发布独立管理**：SessionEvents 接管锁、序号和监听器注册。保持回放先于订阅、锁外回调、监听器快照、深拷贝、异常隔离与原日志类别。公开事件类型仍定义在 session.py，持久化事件读取与会话状态机保持原入口。
7. **列表与菜单投影**：Rail 先建立分组索引，避免反复扫描；保留顺序、重叠成员、重复 ID、对象身份及稀疏聊天数组处理。分区使用一次遍历。Topbar 的缓存和异步资源刷新复用相同投影函数。
8. **复杂度检查**：既有预算按最终结构收紧；增加按领域汇总的静态统计，避免仅移动文件就被当作整体复杂度降低；增加防止重新引入分屏原始 setter 的检查。统计明确不等于运行时 Hook 数或性能。

- 第一批前端测试 113 项通过；Python 相关选择初次有 3 个旧源码位置断言失败，迁移断言后定向复测通过。删除过时的实现形状断言时，用状态行为比较补上约束，没有通过删除失败的功能测试回避问题。
- 核心、协议、运行恢复、架构及前端契约的综合选择：539 项通过。
- 最终协议与事件实现微调后，定向复测 AgentSession、SessionEvents、协议适配器、黄金回放、复杂度工具：124 项通过。该数量与前面的批次重叠，不能相加为独立测试总数。
- Rail 最终稀疏数组处理调整后，两项投影测试通过；其行为比较包含 200 组确定性随机数据。分屏状态比较包含 500 步确定性操作序列。
- Electron 浏览器 RPC 4 项、会话 2 项、选择器生命周期 2 项通过。选择器使用原生接口替身验证挂载、失焦、重开、取消隐藏、换窗和销毁。
- Python 复杂度检查 9758 个作用域、JavaScript 检查 11199 个作用域通过；前端生产构建、修改 Python 文件的 Ruff 检查、git diff --check 通过。
- 实际浏览器与隔离后端/本地模型服务：对话 A/B 草稿隔离、刷新保留选择、pagehide 与重载草稿恢复、真实发送路由到流式响应再到页面显示通过；顶栏菜单能打开。上述路径未出现捕获到的 pageerror。
- **验收缺口**：分屏鼠标拖拽等待第二个面板超时；后续合成拖拽也未找到预期目标区域。尚不能判定为产品回归，也不能宣称真实拖拽验收通过。状态转换已由旧行为比较验证。Electron 未在 Windows/Linux 真机验收。

## 性能结果与边界

结果保存在 full-refactor-*-performance-2026-09-07.json。均为本地微基准，不代表真实模型网络延迟或整机体验。

- 会话事件：每 1000 次发布的中位耗时 33.31 → 33.70 毫秒，约增加 0.38 毫秒（1.15%）。接受这个量级的差异，以换取明确的事件生命周期职责。
- 协议：MockTransport 的 2000 文本片段场景约快 2%–5%；1000 工具参数片段场景约快 28%–31%。各协议输出仍由旧实现生成的 16 组黄金回放校验，包括错误与回调关闭场景。
- Rail：1000 对话、100 分组的合成压力场景显著减少扫描。最终基准在同一 JavaScript realm 执行旧/新函数，替换了早先跨 VM 的测法；约快 97%，仅代表该特定规模下的投影函数，不代表页面整体提速。
